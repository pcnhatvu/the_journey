### 6:00 – 7:30 | Block 1: System Design cơ bản

#### Nội dung học

- **Scalability:** hệ thống đáp ứng tăng trưởng người dùng và lưu lượng như thế nào.
- **Availability:** khả năng hệ thống tiếp tục phục vụ khi có thành phần gặp lỗi.
- **Latency:** thời gian từ lúc nhận request đến lúc trả response.
- **Throughput:** số lượng request hoặc công việc xử lý được trong một khoảng thời gian.
- **Database selection:** khi nào dùng relational database, khi nào cân nhắc NoSQL.

#### Bài tập tư duy

Với Product Service, trả lời bằng văn bản ngắn:

1. Nếu số lượng request tăng gấp 10 lần, thành phần nào có thể trở thành bottleneck?
2. Khi nào cần thêm cache?
3. Vì sao PostgreSQL phù hợp cho phiên bản đầu tiên?
4. Nếu database tạm thời không truy cập được, API nên phản hồi như thế nào?

Checklist:

- [ ] Viết định nghĩa của 5 khái niệm bằng lời của mình.
- [ ] Vẽ sơ đồ đơn giản: client → Product API → database.
- [ ] Ghi lại ít nhất 2 trade-off trong thiết kế.

### 13:00 – 14:30 | Block 2: AWS Fundamentals

#### Mục tiêu

- Hiểu vai trò của EC2, S3, IAM và VPC.
- Phác họa cách một ứng dụng Java có thể chạy trên AWS.
- Không tạo tài nguyên AWS trả phí trong buổi học.

#### Nội dung học và thực hành

- **EC2:** máy ảo để chạy ứng dụng.
- **S3:** lưu trữ object như file và asset.
- **IAM:** quản lý identity, role và quyền truy cập.
- **VPC:** mạng riêng ảo để tổ chức và cô lập tài nguyên.
- Vẽ sơ đồ: người dùng → ứng dụng trên EC2 → database hoặc S3.
- Đọc một ví dụ IAM policy và xác định quyền được cấp.

Checklist:

### 14:45 – 16:15 | Block 3: Docker và Kubernetes

#### Mục tiêu

- Hiểu image, container, port mapping, volume và network.
- Chạy PostgreSQL local bằng Docker Compose.
- Nắm vai trò cơ bản của Kubernetes Pod, Deployment và Service.

#### Thực hành

- Chạy container `hello-world` hoặc `nginx`.
- Thử `docker ps`, `docker images` và `docker logs`.
- Tạo hoặc chạy `docker-compose.yml` để khởi động PostgreSQL.
- Dùng volume để dữ liệu PostgreSQL tồn tại sau khi container được khởi động lại.
- Kiểm tra container và database đang chạy.
- Tìm hiểu cách Kubernetes dùng Pod để chạy container, Deployment để duy trì số replica và Service để cung cấp endpoint ổn định.
- Nếu đã có cluster local (kind, Minikube hoặc Docker Desktop Kubernetes), kiểm tra context bằng `kubectl config current-context` và xem Pod bằng `kubectl get pods`; không cài cluster mới nếu chưa sẵn sàng.

Checklist:

- [ ] Giải thích được image khác container như thế nào.
- [ ] PostgreSQL chạy được bằng Docker Compose.
