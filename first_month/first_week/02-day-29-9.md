### 6:00 – 7:30 | Block 1: Basic System Design

#### Study Topics

- **Scalability:** how a system accommodates growth in users and traffic.
- **Availability:** the ability of a system to continue serving when a component fails.
- **Latency:** the time from receiving a request to returning a response.
- **Throughput:** the number of requests or tasks processed within a period of time.
- **Database selection:** when to use a relational database and when to consider NoSQL.

#### Design Thinking Exercise

For Product Service, answer in writing:

1. If the number of requests increases tenfold, which component could become a bottleneck?
2. When would a cache be needed?
3. Why is PostgreSQL suitable for the first version?
4. If the database is temporarily unavailable, how should the API respond?

Checklist:

- [ ] Draw a simple diagram: client → Product API → database.
- [ ] Record at least 2 design trade-offs.

#### Goals

#### Study and Practice

- **S3:** object storage for files and assets.
- **IAM:** managing identities, roles, and access permissions.
- **VPC:** a virtual private network for organizing and isolating resources.
- Draw a diagram: user → application on EC2 → database or S3.
- Read an example IAM policy and identify the permissions it grants.

### 14:45 – 16:15 | Block 3: Docker and Kubernetes

#### Goals

- Understand images, containers, port mapping, volumes, and networks.
- Run PostgreSQL locally with Docker Compose.
- Understand the basic roles of a Kubernetes Pod, Deployment, and Service.

#### Practice

- Run a `hello-world` or `nginx` container.
- Try `docker ps`, `docker images`, and `docker logs`.
- Create or run `docker-compose.yml` to start PostgreSQL.
- Use a volume so PostgreSQL data persists after the container restarts.
- Check that the container and database are running.
- Learn how Kubernetes uses a Pod to run a container, a Deployment to maintain the number of replicas, and a Service to provide a stable endpoint.
- If a local cluster (kind, Minikube, or Docker Desktop Kubernetes) is already available, check the context with `kubectl config current-context` and view Pods with `kubectl get pods`; don't install a new cluster if not ready.

Checklist:

#### Goals

#### Tasks

- Don't run `terraform apply` or put secrets or cloud credentials in the configuration file.
